DVWA 通常被用来把 payload 敲一遍、看到弹窗就算完成。本文换一个角度：六类漏洞在 Medium 下分别被什么挡住了，以及为什么这些防护大多能被绕开。

目标环境是本地 `http://127.0.0.1/DVWA/`，PHP + MySQL，难度 Medium，工具为 Burp Suite、sqlmap、Nmap、AWVS。

## 命令注入

ping 工具的输入被直接拼进系统命令。Low 下 `127.0.0.1; ls` 即可执行第二条命令。

Medium 会删除 `;` 和 `&&`。但 shell 的分隔符不止这两个：

```
127.0.0.1 | ls
127.0.0.1 & ls
127.0.0.1%0als
```

管道、单与号、换行符都能达到同样效果。修复方式是给参数加 `escapeshellarg()`，并对 IP 字段做格式校验，而不是列举要过滤的字符。

## SQL 注入

`1' OR '1'='1` 在 Low 下让 `WHERE` 条件恒真，返回全部用户记录。

Medium 转义了引号，这条失效。问题在于 `user_id` 是数字型字段，构造 payload 时根本不需要引号：

```
1 OR 1=1
```

转义只能挡住带引号的写法。根本修复是预处理语句，让参数和语句结构分离。

## 盲注

`sqli_blind` 页面只回显用户是否存在。这一个比特就够用：

```sql
1 AND SUBSTRING(database(),1,1)='d'
```

逐字符猜库名。页面回显一致时，还可以用时间盲注，靠延迟判断条件真假：

```sql
1 AND (SELECT 1 FROM (SELECT SLEEP(5))x)
```

修复除了预编译，还要统一错误响应，否则真假差异本身就成了信道。

## 文件上传

上传 `.php` 文件后访问路径即可执行系统命令，是六个里危害最直接的。

调查报告里常见的情况是：前端用 JS 校验扩展名。抓包改请求就绕过去了。

有效的做法需要四层叠加：后端白名单校验扩展名与 MIME；文件重命名；上传目录禁止解析 PHP；文件存到 Web 根目录之外。单看每条都有绕过方法，四层同时存在时成本才够高。

## 两种 XSS 的差别

反射型把参数原样回显，需要诱导受害者点击一个链接。存储型把脚本存进数据库，所有访问者都会触发。

Medium 对两者都替换 `<script`。不用 script 标签即可绕过：

```html
<img src=x onerror=alert(1)>
```

风险等级不同不是因为技术难度不同，而是利用条件和影响范围不同：一个需要交互，一个是持久化。

## 三档防护对比

| 漏洞 | Low | Medium | High |
| --- | --- | --- | --- |
| 命令注入 | 不过滤 | 删除 `&&`、`;` | 更长的黑名单 |
| SQL 注入 | 不过滤 | 转义引号 | 转义并限制长度 |
| 文件上传 | 任意后缀 | 校验 Content-Type | 校验后缀与尺寸 |
| 反射型 XSS | 不过滤 | 替换 `<script` | 更完整的过滤 |
| 存储型 XSS | 不过滤 | 替换 `<script` | 更完整的过滤 |

三档的思路都是列举坏字符。这条路的问题在于，防御方要穷举所有危险写法，攻击方只需找到一个没被列举的。

白名单、参数化、输出编码是另一条路：规定什么输入是允许的。上面每个场景的有效修复都属于这一类。

## 扫描器复核

AWVS 报出 8 个中高风险项。复核结果：4 项与手工验证一致；2 项反射型 XSS 被标为高危，但需要交互且无持久化，按本文标准降为低危；2 项是 `phpinfo` 和目录列举，属于信息暴露，不可直接利用。

扫描器的作用是覆盖范围，定级仍需人工判断。
